Modelo UTXO

Salidas no gastadas

Objetivo: comprender que el estado monetario puede representarse mediante el conjunto de salidas que continúan disponibles y que todavía no han sido gastadas.

El modelo UTXO se relaciona con las salidas de transacción que todavía no han sido gastadas. En lugar de considerar únicamente todo el historial de operaciones, el estado relevante puede representarse mediante el conjunto de salidas que continúan disponibles.

Los materiales proporcionados muestran esta idea al estudiar Mimblewimble. En este diseño, cuando una salida fue creada y posteriormente gastada, puede cancelarse del historial. Las salidas que siguen sin gastarse permanecen como parte del estado actual.

Idea principal Una salida creada que todavía no ha sido gastada forma parte del conjunto UTXO. Cuando posteriormente se consume, deja de formar parte de ese conjunto.

Flujo simplificado

El proceso puede entenderse de la siguiente manera:

  1. Una transacción genera una nueva salida.
  2. Mientras esa salida no sea utilizada posteriormente, permanece dentro del conjunto de salidas no gastadas.
  3. Cuando la salida se utiliza, deja de formar parte del conjunto UTXO.
  4. Las nuevas salidas producidas por las transacciones pasan a formar parte del nuevo estado.
UTXO en una línea Salida creada → salida disponible → salida gastada → nuevas salidas disponibles
Estado de la cadena

¿Por qué importa el conjunto UTXO?

El material sobre esquemas de compromiso utiliza Mimblewimble como ejemplo de una arquitectura en la que el tamaño de la blockchain puede relacionarse con el estado actual y, particularmente, con el conjunto UTXO, en lugar de depender exclusivamente de conservar todo el historial completo.

Como las salidas creadas y después gastadas pueden cancelarse, sobreviven principalmente las salidas que continúan sin gastar y los elementos necesarios para verificar la validez de las transacciones.

Concepto clave El conjunto UTXO representa las salidas que continúan formando parte del estado actual porque aún no han sido utilizadas.
Minería

Proof of Work en Bitcoin

Bitcoin utiliza funciones hash como parte del mecanismo que permite producir nuevos bloques mediante prueba de trabajo.

Bitcoin utiliza SHA-256 aplicado dos veces, también conocido como double-SHA256, tanto en su estructura de bloques como en su mecanismo de Proof of Work.

Durante la minería, los mineros buscan un valor que permita que el hash del encabezado del bloque cumpla una condición determinada por la dificultad de la red.

Uno de los valores que se modifica durante este proceso es el nonce. Cada cambio produce un nuevo resultado al aplicar la función hash.

Condición de Proof of Work El objetivo es encontrar un nonce para el cual el hash del encabezado del bloque quede por debajo del umbral de dificultad establecido.
Proceso

Búsqueda de un bloque válido

  1. Se construye un bloque candidato con la información necesaria para formar su encabezado.
  2. El minero utiliza un valor de nonce.
  3. Sobre el encabezado se aplica double-SHA256.
  4. Se obtiene un hash.
  5. El resultado se compara contra el umbral de dificultad.
  6. Si el hash no cumple la condición, se realiza un nuevo intento.
  7. Cuando el hash queda por debajo del umbral, se ha encontrado una solución válida para la prueba de trabajo.
Flujo simplificado Encabezado del bloque → nonce → double-SHA256 → comparar con dificultad → repetir o aceptar
De cadena artesanal a blockchain

¿Qué aporta la minería?

El ejemplo de blockchain artesanal de los materiales utiliza funciones hash, firmas digitales, encadenamiento y sellado de tiempo para construir bloques.

Sin embargo, ese modelo se presenta explícitamente sin minería, sin consenso distribuido y sin red P2P.

Para pasar de ese esquema educativo a una blockchain real con múltiples participantes, se necesita incorporar mecanismos de consenso como Proof of Work y una red que permita compartir los nuevos bloques.

Diferencia importante El encadenamiento criptográfico explica cómo se relacionan los bloques. La minería añade un mecanismo de Proof of Work para un sistema distribuido con múltiples participantes.
Resumen

UTXO + minería

  • El conjunto UTXO está formado por salidas que continúan sin gastarse.
  • Al gastarse una salida, deja de formar parte del conjunto de salidas disponibles.
  • Bitcoin utiliza double-SHA256 en su mecanismo de Proof of Work.
  • Los mineros buscan un nonce que produzca un hash por debajo del umbral de dificultad.
  • La minería es uno de los mecanismos que diferencia una cadena criptográfica artesanal de una blockchain distribuida real.
Ejercicios

Pon a prueba lo aprendido

Resuelve los siguientes ejercicios sobre el modelo UTXO y el proceso de minería mediante Proof of Work.

Ejercicio 1 · Identificación de UTXO

Ana posee dos salidas no gastadas: una de 0.8 BTC y otra de 0.5 BTC.

Ana quiere realizar una transacción de 1 BTC. Para simplificar, ignora las comisiones.

Pregunta: ¿qué ocurre con los dos UTXO originales y cuánto valor debe regresar como una nueva salida?

Ver respuesta

Los dos UTXO suman 1.3 BTC. Ambos se utilizan como entradas y dejan de formar parte del conjunto UTXO.

Se genera una salida de 1 BTC para el destinatario y otra salida de 0.3 BTC como cambio.

Ejercicio 2 · Salidas gastadas y no gastadas

Una transacción crea tres nuevas salidas:

  • Salida A: 0.4 BTC
  • Salida B: 0.3 BTC
  • Salida C: 0.2 BTC

Más tarde, las salidas A y C se utilizan en nuevas transacciones.

Pregunta: ¿cuál de las tres salidas continúa formando parte del conjunto UTXO?

Ver respuesta

Únicamente la Salida B de 0.3 BTC continúa formando parte del conjunto UTXO, porque todavía no ha sido gastada.

Ejercicio 3 · Proof of Work

Supón que, de manera simplificada, la red exige que el hash encontrado sea menor que:

Umbral 0000FFFF...

Un minero obtiene el siguiente hash:

Hash obtenido 00001234...

Pregunta: ¿cumple este hash con la condición del ejercicio?

Ver respuesta

Sí. En este ejemplo simplificado, 00001234... es numéricamente menor que 0000FFFF....

Por lo tanto, el resultado cumple con el umbral definido para el ejercicio.

Ejercicio 4 · Nonce y minería

Un minero calcula el hash del encabezado de un bloque, pero el resultado no cumple con el objetivo de dificultad.

Pregunta: ¿qué puede hacer para realizar un nuevo intento?

Ver respuesta

Puede modificar valores utilizados para construir el encabezado, entre ellos el nonce, y volver a calcular el hash.

El proceso se repite hasta obtener una solución que cumpla las reglas de Proof of Work.

Recuerda UTXO → identifica salidas disponibles. Minería → busca una solución válida de Proof of Work.
